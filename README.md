# 売上管理ツール(オフライン対応PWA)

Progressive Web App (PWA) として動作する、オフライン環境でも使える売上管理ツールです。
ビルド不要の素の HTML / CSS / JavaScript で構築されています。

**レジ / 売上履歴 / 集計レポート / 商品マスタ管理 / 顧客管理 / 設定** の6画面を実装しています。

**売上データと商品マスタ(在庫を含む)は Firebase(Firestore)でリアルタイム同期しています**(「共有コード」を合わせた端末同士でリアルタイムに共有・オフライン時はローカルにキューイングして復帰時に自動同期)。顧客管理は引き続き各端末内の IndexedDB にのみ保存されるローカルデータです。

公開URL: https://tukuyomi1189.github.io/sales-management-pwa/

操作マニュアル(PDF・画像入り): [docs/操作マニュアル.pdf](docs/操作マニュアル.pdf)(公開URL: https://tukuyomi1189.github.io/sales-management-pwa/docs/操作マニュアル.pdf )

## 主な機能

### レジ(売上入力)
POSレジのように誰でも操作できることを目指した画面です。iPadの横向き(左に商品ボタン、右にカート)を基本に、縦向き・スマホでも使えます。
- 登録済みの商品をボタンから**タップするだけでカートに追加**。同じ商品を続けてタップすると数量が+1される。ボタンの並び順は商品コード順で固定(売上のたびに並びが変わらない)
- **ボタンの並べ替え**: 「並べ替え」を押すとボタンをドラッグして好きな位置に動かせる。「完了」で保存、「コード順に戻す」で初期の並びに戻る。並びは端末ごとに保存され、商品コードで記憶するのでJSONで商品を移しても崩れない(商品コードのない商品は端末内のIDで記憶)
- **年齢確認**: 商品マスタで「年齢確認が必要な商品」にした商品は、ボタン・カート・会計画面・売上履歴に赤い「年齢確認」の印が出る(表示のみで、会計は止めない)
- **カテゴリタブ**で商品を絞り込み(商品マスタのカテゴリから自動生成、カテゴリごとに色分け)。在庫0の商品は「在庫切れ」と表示
- **バーコード対応**: 検索欄で商品コードを読み取る(または入力して Enter)と、そのままカートに追加
- カートはレシート風の1行表示。数量は ＋/－ ボタンで増減、行をタップすると単価の変更・削除ができる。在庫を超える数量は「在庫不足」と表示(会計はブロックしない)
- 「全取消」でカートを空にできる(直後に表示される「元に戻す」で復元可能)
- 顧客(任意)・メモは「顧客・メモ」を開いて指定
- **お会計**: お預かり金額を「ちょうど」と金額ボタン(初期値は「+¥1,000」「+¥5,000」「+¥10,000」。「設定」で変更可)とテンキーで入力し、お釣りを表示。金額ボタンは押すたびに加算される(500を2回で¥1,000)。確定すると完了画面にお釣りを大きく表示し、「次のお客様」(または画面の外側をタップ)で注文画面に戻る。お預かり入力中は外側をタップしても閉じない(入力した金額が消えないように)。完了画面の「この会計を取り消す」で直前の会計を取り消せる(在庫も戻り、商品はカートに戻る)
- 支払い方法は現在「現金」のみ。[js/register.js](js/register.js) の `PAYMENT_METHODS` に追加すると、会計画面に支払い方法の選択が自動で表示される(`tender: false` の方法はお預かり入力なしで合計額で確定)。選んだ方法は売上の `payment` に保存される
- 売上日時は会計を確定した瞬間の日時を自動記録。編集時も元の売上日時は変わらない
- 売上を登録すると、明細分の商品在庫が自動的に減算される(削除・編集時は自動的に復元)
- 登録はサーバーの応答を待たずに即完了する(オフラインでも同じ)。クラウドへの同期はバックグラウンドで行われる
- 営業中に画面が消えないよう、レジ画面を開いている間はスリープを抑止(Screen Wake Lock API。iPadOS 18.4以降のホーム画面アプリで有効。非対応の場合はiPadの「自動ロック」設定に従う)

### 売上履歴
- 登録済みの売上の一覧(支払い方法・お預かり・お釣りも表示)。クラウドへ未同期の売上には「同期待ち」と表示される
- 顧客名・商品名・メモでの検索
- 「編集」でレジ画面に読み込んで修正できる(「更新する」で保存)
- チェックボックスで複数選択してまとめて削除可能。削除前に確認ダイアログを表示し、削除すると明細分の在庫が元に戻る
- JSONエクスポート / インポート(端末間でのデータ移行用。インポートしても在庫数は変更されない)

### 設定
- **在庫数の表示**: レジの商品ボタンの「残り ◯個」を表示するかどうかを切り替えられる(お客様に在庫数を見せたくないときはオフ)。オフでも「在庫切れ」は表示され、カートの在庫超過は「在庫不足」とだけ表示する。端末ごとの設定(localStorage の `sales-management-show-stock`)
- **お預かりボタンの金額**: 会計画面で「ちょうど」の後ろに並ぶボタンの金額を変更できる(例: 300, 500, 1000。最大8個)。端末ごとの設定(ブラウザの localStorage に保存)
- **共有コードによるリアルタイム同期(パイロット)**: 同じ共有コードを設定した端末同士で売上データがリアルタイムに共有される。オフライン中に登録した売上はローカルにキューイングされ、オンライン復帰時に自動的に同期される。「ローカルの売上データをアップロード」ボタンで、既存のローカル専用データ(Firestore導入前の売上)をクラウドに移行できる

### レポート(集計)
- 期間プリセット(今月 / 先月 / 直近7日 / 直近30日 / 全期間 / カスタム)による絞り込み
- 期間合計売上・件数・平均客単価のサマリー表示
- 売上推移グラフは「日別」(期間が長い場合は自動的に月別集計に切り替え)と「時間帯別」(指定した1日の0〜23時の売上)を切り替え可能
- 商品別・顧客別の売上ランキング(商品別は金額と数量を表示。無償の商品も数量で確認できる)
- **精算(精算先ごと)**: 合同サークル・委託などで売上を相手ごとに分けるための集計。商品マスタの「精算先」ごとに、集計期間内の商品別の数量・金額、精算先ごとの小計、総計を表示する
  - 商品のチェックボックス(精算先の見出しで一括選択)で、選んだ商品だけの合計を画面下に表示
  - 「CSVで保存」で精算結果をCSV(Excelで開けるUTF-8 BOM付き)に保存
  - 売上の明細には**売れた時点の精算先**を記録する。精算先を後から変えても過去の売上の精算先は変わらない(同じ商品が期間内で2人に分かれて表示されることがある)。精算先を記録していない売上(この機能の導入前の売上や、売った時点で精算先が未設定だった売上)は、現在の商品マスタの精算先で集計する。どちらもなければ「未設定」

### 商品マスタ管理
- **共有コードが同じ端末すべてで共有**(Firestore の `workspaces/{共有コード}/products`)。PCで登録・編集した商品は、iPadなど他の端末にもすぐ反映される。JSONでの受け渡しは不要
- **在庫も共通**: 会計・取消・編集で動く在庫は Firestore の `increment` で増減するので、2台で同時に売っても数が合う
- この機能の導入前に端末内(IndexedDB)だけにあった商品は、「設定」または商品マスタ・レジに出る案内の「この端末の商品をクラウドへアップロード」で一度だけクラウドへ移す。商品コードがすでにクラウドにある商品は上げない(重複防止)。元のIDを引き継ぐので、過去の売上も同じ商品として集計される
- Firestore のルールで商品の共有が許可されていない場合(ルール未反映)は、端末内の商品マスタで動作を続け、その旨を表示する
- 商品の登録・編集・削除(商品コード / 商品名 / カテゴリ / 単価 / 在庫数 / 単位 / メモ)
- 商品名・商品コード・カテゴリでのキーワード検索
- 一覧の見出し(商品コード・商品名・カテゴリ・単価・在庫数・更新日時)を押すと並べ替え(もう一度押すと逆順)。選んだ並びは端末に記憶される
- 年齢確認: 「年齢確認が必要な商品」にチェックすると、レジや会計画面に印が出る
- 精算先(任意): 合同・委託などで売上を分ける相手。入力済みの精算先は候補として表示される
- 在庫少バッジ表示、登録件数・在庫合計・在庫評価額のサマリー表示
- **在庫の共有(無償譲渡など)**: 「在庫を共有する商品」で別の商品を選ぶと、その商品の在庫を共通で使う。例えば「新刊 A5本(P-011, ¥1,000, 在庫30)」に対して「新刊 A5本(無償)(P-011F, ¥0, 共有元 P-011)」を作ると、レジにはボタンが2つ並び、どちらを会計しても P-011 の在庫が減る。売上・レポートでは別商品として記録されるので、有償分と無償分を分けて数えられる
  - 共有元は**商品コードで指定**する(JSONインポートで内部IDが変わっても関係が保たれるように)。そのため共有元には商品コードが必要
  - 共有している側の在庫数は使われない(入力欄は無効になる)。在庫の入力は共有元で行う
  - 共有元の商品コードを変更すると、共有している商品の参照も自動で更新される。共有されている商品は削除できず、商品コードを空にもできない
  - 在庫合計・在庫評価額は共有元の在庫だけで計算する(二重計上しない)
  - レジでは0円の商品に「無償」、在庫を共有している商品に「共通」と表示。在庫不足の判定は、同じ在庫を使う商品のカート内数量の合計で行う
- JSONエクスポート / インポート(バックアップ・復元用)

### 顧客管理
- 顧客の登録・編集・削除(顧客名 / 担当者名 / 電話番号 / メール / 住所 / メモ)
- 顧客名・担当者名での検索
- JSONエクスポート / インポート(端末間でのデータ移行用)

### 共通
- オンライン / オフライン状態の表示
- ホーム画面へのインストール(Add to Home Screen)対応
- **新バージョン検知バナー**: アプリを開いたままの状態でも、タブ/アプリがアクティブになるたびに新しいバージョンがないか確認します。新しいバージョンが見つかると画面上部に通知バーが表示され、「再読み込みする」ボタンで反映できます(手動でアプリを閉じ直す必要はありません)

## 技術スタック

- 素の HTML / CSS / JavaScript(ビルドツール・フレームワーク不使用)
- ローカルデータ保存: IndexedDB([js/db.js](js/db.js))— 商品・顧客はここに保存
- 売上データ: [Firebase Firestore](js/firebase-init.js)(モジュール版SDKをCDNから動的import)。オフライン永続化キャッシュを有効化しており、Firestore自体がオフラインキュー+オンライン復帰時の自動同期を担う。認証は匿名認証のみ(アカウント作成不要)
- オフラインキャッシュ: Service Worker([service-worker.js](service-worker.js))によるアプリシェル+Firebase SDKのキャッシュ
- 画面切り替え: ハッシュベースの簡易ルーター([js/router.js](js/router.js))
- グラフ: 外部ライブラリを使わず SVG を直接描画(CDN依存をなくしオフラインでも確実に表示するため)
- PWAマニフェスト: [manifest.json](manifest.json)

## データモデルのポイント

- 売上(`sales`)の明細には、登録時点の商品名・単価をスナップショットとして保存しています。そのため商品マスタを後から編集・削除しても、過去の売上記録の表示内容は変わりません。
- 売上IDはFirestoreのドキュメントID(文字列)です。以前のIndexedDB版(自動採番の数値ID)とは形式が異なります。
- 売上登録・編集・削除に伴う商品在庫の増減は、各端末のローカルIndexedDB(商品マスタ)に対して行われます。売上本体(Firestore)と在庫(IndexedDB)は別々のデータベースなので、以前のような単一トランザクションでの一括更新ではなく、順番に行うベストエフォートな更新です。
- 売上には支払い情報 `payment`(`method`: 支払い方法ID、現金の場合は `received`: お預かり / `change`: お釣り)を保存します。この機能の導入前に登録した売上には `payment` がありません。
- 売上の日時は会計を確定した瞬間の日時([js/db.js](js/db.js) の `SalesDB.add`)で自動的に決まり、以後の編集では変更されません(`SalesDB.update` は `date`/`createdAt` を上書きしない設計)。

## リアルタイム共有(売上データ・パイロット導入)

売上データは Firebase Firestore を通じて、**「共有コード」を合わせた端末同士でリアルタイムに共有**されます。ログインアカウントは不要で、共有コードそのものがアクセス制御になります。

### 使い方
1. 「設定」タブの「共有コード」を確認する(初回アクセス時に自動生成されるランダムな8桁のコード)
2. 別の端末で同じデータを見たい場合、その端末の「設定」タブで「別のコードに参加」を押し、1で確認したコードを入力する(入力後ページが再読み込みされます)
3. 以降、どちらの端末で売上を登録・編集・削除しても、もう一方の端末にリアルタイムに反映されます(オンライン時)
4. オフライン中に登録した売上は端末内にキューイングされ、オンラインに復帰すると自動的に同期されます
5. Firestore導入前からローカル(IndexedDB)に残っている売上データがある場合は、「ローカルの売上データをアップロード」ボタンで現在の共有コードのクラウドに移行できます(在庫数は変更されません。二重アップロードすると重複するので注意)

### 重要な注意点
- **共有コードはパスワードとして扱ってください。** ログインの仕組みがないため、コードを知っている人は誰でもそのデータを読み書きできます([firestore.rules](firestore.rules)参照)。
- 商品マスタ(在庫を含む)も共有コードで同期されます。顧客管理は対象外で、引き続き端末ごとのローカルデータです(複数端末で使う場合はJSONエクスポート/インポート)。
- お預かりボタンの金額・レジボタンの並び・商品一覧のソートは端末ごとの設定です。
- 複数人が同時に同じ売上を編集した場合、最後に書き込まれた内容が残ります(competing writesの詳細な競合解決は行っていません)。
- 売上データは Google Cloud(Firebase)上のプロジェクトに保存されます。無料のSparkプランで運用しており、追加費用は発生しない想定の使用量です。

### セキュリティ設定のメモ
- Firebase の Web API キーには **参照元(HTTPリファラー)制限** をかけてあります。許可されているのは本番ドメイン(`https://tukuyomi1189.github.io/*`)と、ローカル開発でよく使うポート(`localhost`/`127.0.0.1` の 8080・8000・3000)のみです。別のポートでローカル動作確認をする場合は、[Google Cloud Console の認証情報ページ](https://console.cloud.google.com/apis/credentials?project=sales-management-pwa-36ea0c)からそのポートを許可リストに追加してください。
- このAPIキー自体は(Firebase の仕様上)公開されて問題ない値です。実際のデータアクセス制御は上記の共有コード方式と `firestore.rules` が担っています。参照元制限は「万一キーが別サイトに流用されても、本来のドメイン以外からは動かない」ようにする多層防御です。

## オフライン環境での使用方法

このアプリは **一度読み込むとオフラインでも完全に動作します**。仕組みは次の3段構えです。

1. **Service Worker がアプリ本体(HTML/CSS/JS/アイコン/Firebase SDK)をキャッシュ**するため、ネットワークがなくても画面が表示されます。
2. **商品・顧客データは IndexedDB に保存**されるため、ネットワークがなくても登録・編集・削除・検索がすべて行えます。
3. **売上データは Firestore のオフライン永続化キャッシュに保存**されるため、ネットワークがなくても登録・編集・削除・集計がすべて行え、オンライン復帰時に自動的にクラウドへ同期されます。

### 注意点

- Service Worker は **HTTPS または localhost でしか動作しません**。`file://` で直接 `index.html` を開いたり、`http://` の LAN IP(例: `http://192.168.x.x:8080`)でアクセスした場合はオフラインキャッシュが有効になりません。
- 商品・顧客データは **端末・ブラウザごとに独立**しています(PCとスマホ、Chrome と Safari 等で共有されません)。端末間でデータを移したい場合は下記の「端末間でデータを共有する」を参照してください。売上データは前述の「共有コード」でリアルタイムに共有できます。
- **コードを更新してデプロイするときは、必ず [service-worker.js](service-worker.js) 冒頭の `CACHE_VERSION` を上げてください。** アプリ本体(HTML/CSS/JS)はバージョンごとにまとめてキャッシュされ、`CACHE_VERSION` が変わったときだけ全ファイルが一度に新しい版へ切り替わります(古いファイルと新しいファイルが混ざって画面が壊れるのを防ぐため)。利用者側には「新しいバージョン」バナーが表示され、「再読み込みする」で反映されます
  - 新しい版のファイルは、ブラウザのHTTPキャッシュ(GitHub Pagesは10分)を使わずサーバーから取得してキャッシュします
- 既存のブラウザ環境に商品マスタ(v1)のデータがある場合でも、IndexedDBのバージョンアップ処理により **既存の商品データを保持したまま** 顧客ストアが追加されます。

## ローカルで動かす

```bash
cd sales_management_project
python -m http.server 8080
```

ブラウザで `http://localhost:8080` を開きます(`localhost` は secure context 扱いのため Service Worker が有効になります)。一度読み込めば、以降はネットワークを切っても利用できます。

## 端末間でデータを共有する

- **売上データ**: 前述の「リアルタイム共有(売上データ・パイロット導入)」の共有コードを使うのが基本の方法です。自動・リアルタイムに同期されます。
- **商品マスタ・顧客管理**: リアルタイム同期の対象外なので、各画面の **JSONエクスポート / インポート** を使って手動でファイルを受け渡します(売上データも、別のクラウドプロジェクト/共有コードへ一括で持っていきたい場合はJSON経由が使えます)。

1. 移行元の端末で、商品マスタ・顧客管理(・必要なら売上履歴)の画面から「JSONエクスポート」でファイルをダウンロードする
2. ダウンロードしたJSONファイルを、メールやクラウドストレージ等で移行先の端末に送る
3. 移行先の端末で、同じ画面の「JSONインポート」からファイルを選択する(**商品 → 顧客 → 売上の順**にインポートすることを推奨。売上明細は商品名などをスナップショットとして保持しているため、順序を守らなくても表示は壊れませんが、この順だと在庫の数字が最も分かりやすくなります)

### 注意点
- インポートは既存データに**追加**されます(置き換えではありません)。同じファイルを2回インポートすると重複します。
- 売上をインポートしても、**商品の在庫数は変更されません**。売上ごとに在庫を再計算して二重に減算してしまうのを避けるためです。エクスポート時点の在庫数を反映したい場合は、商品マスタのJSONも一緒にインポートしてください。
- 売上データは元の売上日時(登録した瞬間の日時)を保持したままインポートされます。

## スマホで使う

1. 公開URL(https://tukuyomi1189.github.io/sales-management-pwa/ )をスマホのブラウザで開く
2. ホーム画面に追加してインストール
   - **Android (Chrome)**: 右上メニュー(⋮) → 「アプリをインストール」または「ホーム画面に追加」
   - **iPhone (Safari)**: 共有ボタン → 「ホーム画面に追加」
3. インストール後はホーム画面のアイコンから単体アプリとして起動でき、機内モードでも利用できます

### スマホ向けの画面(幅760px未満)
iPad / PC の画面はそのままで、スマホでは次のレイアウトに切り替わります。
- **画面下のタブバー**: アイコン付きのタブを画面下に固定。ヘッダーは細くして表示領域を広げています
- **レジ**: 商品ボタンを画面いっぱいに表示し、下に「点数・合計・明細・お会計」のバーを固定。「明細」でカートが下から開きます(背景タップ / 「閉じる」で戻る)
- **お会計**: 全画面表示で、「会計を確定」ボタンは常に画面下に表示
- **売上履歴・商品マスタ**: 1件ずつカード表示。JSON入出力などの操作は「…その他」にまとめています
- **商品マスタ**: 一覧を先に表示し、「＋ 商品を追加」または「編集」でフォームを開きます。並び順はプルダウンで切り替え
- **レポート**: 集計タイルを横3列、開始日・終了日を横並びに

**iPad / iPhone の注意**: ホーム画面に追加したアプリと Safari とでは、保存されるデータ(商品・顧客マスタ)が別々です。Safari で商品を登録してからホーム画面に追加すると、アプリ側では商品が空になります。**先にホーム画面に追加し、そのアプリから商品を登録**してください(または JSON インポート)。
